**type** | **string** | What the action does. &#x60;telegram&#x60;, &#x60;webhook&#x60; and &#x60;push&#x60; notify through a notification channel. &#x60;update_entity&#x60;, &#x60;create_entity&#x60; and &#x60;run_entity_action&#x60; write records. &#x60;http_request&#x60; calls an API and can keep parts of its JSON response on the trigger record. |
**config** | **object** | Configuration by &#x60;type&#x60;. Every string marked *template* renders variables such as &#x60;{entity.id}&#x60;, &#x60;{entity.external_key}&#x60;, &#x60;{values.&lt;attribute slug or id&gt;}&#x60;, &#x60;{previous.&lt;attribute&gt;}&#x60;, &#x60;{values.&lt;reference attribute&gt;.&lt;attribute of the referenced record&gt;}&#x60;, &#x60;{automation.name}&#x60; and &#x60;{timestamp}&#x60;.  **Notifications** - &#x60;telegram&#x60;: &#x60;{\&quot;channel_id\&quot;: \&quot;&lt;telegram channel id&gt;\&quot;, \&quot;chat_id\&quot;: \&quot;&lt;telegram chat id&gt;\&quot;, \&quot;message_template\&quot;: \&quot;&lt;template&gt;\&quot;}&#x60; - Webhook and HTTP request targets on private, loopback or link-local networks (&#x60;localhost&#x60;, &#x60;10.0.0.0/8&#x60;, &#x60;192.168.0.0/16&#x60;, …, also after DNS resolution and redirects) are refused: the action fails with &#x60;Target resolves to a private network address&#x60;.  **HTTP request with response mapping** - &#x60;http_request&#x60;: the &#x60;webhook&#x60; config (&#x60;channel_id&#x60;, &#x60;method&#x60;, &#x60;url_template&#x60;, &#x60;headers&#x60;, &#x60;query_params&#x60;, &#x60;payload_template&#x60;) plus &#x60;\&quot;timeout_seconds\&quot;: &lt;1-30, default 10&gt;&#x60; and &#x60;\&quot;response_mapping\&quot;: {\&quot;&lt;attribute slug or id&gt;\&quot;: \&quot;&lt;JSONPath&gt;\&quot;}&#x60; (at most 50 entries). Paths use &#x60;$&#x60;, &#x60;.name&#x60;, &#x60;[&#39;name&#39;]&#x60; and &#x60;[index]&#x60;, e.g. &#x60;$.data.items[0].id&#x60;. - A status outside 2xx, no response, or a response over 1 MB fails the action. With a mapping the response must be JSON and every path must resolve; otherwise the action fails and writes nothing. Mapped values are written to the trigger record in one update, as the automation and through the template&#39;s Rules, like &#x60;update_entity&#x60;: numbers and booleans as text, JSON &#x60;null&#x60; clears the attribute, an object or list is stored as JSON and only in a text or markdown attribute. - A mapping needs a trigger with a &#x60;templateId&#x60;, and whoever saves the automation needs the rights to edit that template&#39;s records. Without a mapping the call needs no record. - The execution records &#x60;details&#x60; per action: &#x60;status_code&#x60;, &#x60;written&#x60; (the mapped attributes) and &#x60;response_excerpt&#x60; (the first 2 KB of the body), also when the action fails. - Example, enrich a new lead from its domain: &#x60;{\&quot;channel_id\&quot;: \&quot;&lt;enrichment API channel id&gt;\&quot;, \&quot;method\&quot;: \&quot;GET\&quot;, \&quot;url_template\&quot;: \&quot;companies/{values.company_domain}\&quot;, \&quot;timeout_seconds\&quot;: 15, \&quot;response_mapping\&quot;: {\&quot;company_size\&quot;: \&quot;$.company.employees\&quot;, \&quot;industry\&quot;: \&quot;$.company.industry\&quot;}}&#x60;.  **Record writes.** They run as the automation (history and audit show &#x60;automation:{id}&#x60; as the author), go through the template&#39;s Rules, quotas and value validation like any other write, and are checked when the automation is saved: you need the rights to create and edit records of every template an action writes to, and every attribute, template and action named must exist. A write that is refused (a rule violation, a failed action precondition, an invalid value, a missing target record) fails that action and is recorded on the execution; the other actions still run. Writes made by an automation never fire automations triggered by created, updated, attribute-changed or action-executed events, so automations cannot chain or loop through their own writes; they do start other automations&#39; time-based timers. - &#x60;update_entity&#x60;: &#x60;{\&quot;target\&quot;: &lt;target&gt;, \&quot;values\&quot;: {\&quot;&lt;attribute slug or id&gt;\&quot;: \&quot;&lt;template&gt;\&quot;}}&#x60;. Partial update of the target record. A value that renders to an empty string clears the attribute. Example: &#x60;{\&quot;target\&quot;: {\&quot;kind\&quot;: \&quot;trigger_entity\&quot;}, \&quot;values\&quot;: {\&quot;escalation_note\&quot;: \&quot;No reply to {values.title} yet\&quot;, \&quot;escalated_at\&quot;: \&quot;{timestamp}\&quot;}}&#x60;. - &#x60;create_entity&#x60;: &#x60;{\&quot;template_id\&quot;: \&quot;&lt;template slug or id&gt;\&quot;, \&quot;values\&quot;: {\&quot;&lt;attribute slug or id&gt;\&quot;: \&quot;&lt;template&gt;\&quot;}, \&quot;external_key\&quot;: \&quot;&lt;optional template&gt;\&quot;}&#x60;. Creates a record; a key that renders empty means no key, a key a live record already holds fails the action. Example: &#x60;{\&quot;template_id\&quot;: \&quot;contract\&quot;, \&quot;values\&quot;: {\&quot;customer\&quot;: \&quot;{values.customer.id}\&quot;, \&quot;renewal_date\&quot;: \&quot;{values.close_date}\&quot;}, \&quot;external_key\&quot;: \&quot;deal:{entity.id}\&quot;}&#x60;. - &#x60;run_entity_action&#x60;: &#x60;{\&quot;target\&quot;: &lt;target&gt;, \&quot;action_slug\&quot;: \&quot;&lt;entity action slug&gt;\&quot;, \&quot;values\&quot;: {\&quot;&lt;field slug or id&gt;\&quot;: \&quot;&lt;template&gt;\&quot;}}&#x60;. Runs a named entity action on the target record, so its precondition, required fields and presets apply; &#x60;values&#x60; may only name the action&#39;s fields. Prefer it over &#x60;update_entity&#x60; for status changes that have an action. Example: &#x60;{\&quot;target\&quot;: {\&quot;kind\&quot;: \&quot;trigger_entity\&quot;}, \&quot;action_slug\&quot;: \&quot;escalate\&quot;, \&quot;values\&quot;: {\&quot;reason\&quot;: \&quot;No reply within 24 hours\&quot;}}&#x60;. - Values are written exactly as rendered, in the attribute&#39;s input format: a list attribute takes a list item id and a reference attribute a record id (&#x60;{values.&lt;reference attribute&gt;.id}&#x60; renders the id a reference of the trigger record holds), while &#x60;{values.&lt;list attribute&gt;}&#x60; renders the item&#39;s label. - &#x60;&lt;target&gt;&#x60; is &#x60;{\&quot;kind\&quot;: \&quot;trigger_entity\&quot;}&#x60; (the record that fired the automation) or &#x60;{\&quot;kind\&quot;: \&quot;reference\&quot;, \&quot;attribute_id\&quot;: \&quot;&lt;reference attribute slug or id&gt;\&quot;}&#x60; (the record that reference attribute of the trigger record points at). Both need a trigger with a &#x60;templateId&#x60;. |
